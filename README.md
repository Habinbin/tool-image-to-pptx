# tool-image-to-pptx

이미지를 드롭하면 **한 장씩 슬라이드에 꽉 채운 PPTX**로 내보낸다.

Figma에서 뽑은 이미지를 빈 슬라이드에 하나씩 드래그해 붙이던 작업을 대체한다.

## 클릭 예산: 2

```
1. 이미지 드롭
2. PPT 내보내기
```

묻지 않고 정하는 것:

| 항목          | 결정 방식                                                                     |
| ------------- | ----------------------------------------------------------------------------- |
| 슬라이드 비율 | 첫 이미지의 픽셀 비율에서 감지. 프리셋(16:10 / 16:9 / 4:3)으로 덮어쓸 수 있다 |
| 슬라이드 순서 | 파일명 natural sort (`2.png` → `10.png`, 사전순 아님). 드래그로 재정렬 가능   |
| 파일명        | `slides.pptx`. 수정 가능하되 필수 아님                                        |
| 이미지 품질   | 원본 바이트 그대로 삽입. 재인코딩하지 않는다                                  |

## 실패 체크리스트

- [x] 슬라이드 수 == 입력 이미지 수
- [x] 각 이미지가 슬라이드를 정확히 채운다 (off 0,0 / ext == 슬라이드 크기)
- [x] `10.png` 가 `2.png` 뒤에 온다
- [x] 비율이 다른 이미지가 섞여도 슬라이드 크기는 하나로 유지된다
- [x] 원본 바이트가 보존된다 (재인코딩·화질 저하 없음)
- [x] PNG / JPEG / GIF / WebP 의 크기를 디코딩 없이 읽는다 (대용량에서 메모리 안전)
- [x] 손상된 이미지 하나가 나머지 전체를 실패시키지 않는다
- [x] 생성된 PPTX를 풀었을 때 PowerPoint가 요구하는 파트가 전부 있다
- [ ] 실제 PowerPoint / Google Slides 에서 열린다 _(사람 확인 필요)_

`[x]` 는 `*.spec.ts` 로 자동 검증된다.

```sh
pnpm test                                      # repo 안 픽스처만 — 어디서든 돈다
REAL_SAMPLES_DIR=/path/to/exports pnpm test    # 실제 Figma 내보내기까지 포함
```

기본 테스트는 `src/fixtures/` 의 작은 PNG 만 쓴다 — 어느 체크아웃에서도 돌아야 하고
CI 에서도 돌아야 하기 때문이다. 실제로 감당해야 하는 것은 4320×2700 짜리 수십 장
(수백 MB)이라, 그 검증은 `REAL_SAMPLES_DIR` 를 준 사람만 돌리는 옵트인 테스트로 둔다.

## 구조

| 파일                  | 역할                                       |
| --------------------- | ------------------------------------------ |
| `src/natural-sort.ts` | 파일명 자연 정렬                           |
| `src/image-size.ts`   | 헤더만 읽어 이미지 크기 취득 (디코딩 없음) |
| `src/aspect.ts`       | 비율 프리셋과 감지                         |
| `src/pptx.ts`         | OOXML 생성                                 |
| `src/App.svelte`      | UI. `$ui` primitive로만 조립               |
